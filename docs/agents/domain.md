# Domain docs

## Before exploring

This repository uses a single-context layout:
- Read `GLOSSARY.md` at the repository root, when present.
- Read relevant decisions in `docs/adr/`, when present.

If these files are absent, proceed silently. Domain-modeling work creates
them lazily when terminology or decisions are resolved.

## Vocabulary

Use the glossary's terms in issues, proposals, hypotheses, and tests.
If a needed concept is missing, reconsider the term or note the gap
for domain modeling.

## Decisions

Surface conflicts with existing ADRs explicitly, naming the ADR and
explaining why the decision may need reopening.
